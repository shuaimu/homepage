Slides 1–64 form the core lecture. The suggested timings in the speaker notes total 96 minutes, including discussion and the separate compaction-policy examples. For an 80-minute route, omit the prior-lecture review on slides 6–13 (10 minutes) and the discussion activities on slides 23 and 62–63 (7 minutes), leaving one minute for transitions. Slide 65 opens the appendix; slides 66–72 are optional material on hardware, key/value separation, read costs, project history, the original utilization chart, and the talk’s amplification estimates. Presenting all appendices adds approximately 12 minutes; they are also included in the student handout.

Slides 2–3 introduce LevelDB’s origins and Facebook’s RocksDB fork, using Google’s 2011 announcement and Facebook’s 2013 announcement. These add about two minutes before the lecture’s central question.

Slide 14 opens the section with “Why do we need LSM on SSD?” Slides 15–17 introduce flash write costs with matched four-page diagrams: an HDD overwrites one page in place; an SSD writes the updated page and copies the three live pages to fresh space before erasing the old block, producing 4× write amplification in this example. The SSD diagram combines an update with later reclamation; it does not imply copying a block on every update. Slide 17 connects these costs to LSM batching and compaction. Page sizes and counts are illustrative. Background: OSTEP’s SSD chapter. Slide 18 introduces the compaction-policy section. Slides 19–21 give leveled, universal/tiered, and FIFO one worked diagram each; mechanics were checked against the RocksDB compaction documentation and FIFO documentation. Slide 22 compares the measurements and defines write amplification and space overhead beneath the table; slide 23 closes the section with suggested policies and reasons beside each application. Source links and qualifications stay in the speaker notes.

Slides 24–29 introduce Bloom filters from first principles: a title divider, membership testing, construction with hashes, definite absence, false positives, and RocksDB’s use of filters to skip SST lookups. One eight-bit example carries through construction and queries; its hash outputs are illustrative. The section takes about nine minutes, seven more than the earlier single-slide introduction. Background: Bloom’s original paper and RocksDB’s filter documentation.

The later slides define terms and explain the mechanisms directly on the page: checksum boundaries, recovery, shared host budgets, WAL durability, file pinning, and timestamped reads. Short additions explain checksum creation and verification (37), WAL recovery (48), independent shard sequence numbers (57), and one worked answer to the design discussion (63). Concrete examples supplement the existing diagrams without reducing type size or line spacing. Suggested timings are redistributed within those topics; the core now totals 96 minutes.

Slides 55–56 compare sequence numbers with user timestamps and show two versions carrying both fields. The worked reads demonstrate that a snapshot’s sequence limit and the application’s timestamp limit both apply. Local sequence numbers do not provide a common clock across shards. These explanations use the RocksDB timestamp documentation and snapshot documentation to clarify the paper’s concepts, without treating newer APIs as 2021 features.

Build

Requires Typst 0.15 or later (checked with 0.15.1). Imports pin Touying 0.7.4 and CeTZ 0.5.2. Typst downloads packages on the first build and caches them outside this repository.

make -C teaching/db/26fa/slides

Or, from this directory:

typst compile DB26fa-RocksDB.typ
typst compile --input handout=true DB26fa-RocksDB.typ DB26fa-RocksDB-handout.pdf
typst eval --in DB26fa-RocksDB.typ --pretty 'query(<pdfpc-file>).first().value' > DB26fa-RocksDB.pdfpc

For an explicit external package cache:

make -C teaching/db/26fa/slides TYPST_FLAGS='--package-cache-path /tmp/typst-packages'

rocksdb-theme.typ defines the typography and layout. Titles use STIX Two Text / Times New Roman; body text uses Helvetica Neue / Arial; records use Menlo / DejaVu Sans Mono. On Linux, install STIX Two Text and set sans-font to an installed font such as Liberation Sans. Changing fonts can change wrapping, so inspect the regenerated PDF on another platform. rocksdb-diagrams.typ contains the editable CeTZ drawings. The original survey chart is retained as a source image in assets/, with provenance in its README. Slide text, source references, and speaker notes are in DB26fa-RocksDB.typ.

To preview the homepage, run from the repository root with a throwaway Jekyll destination. Explicitly loading the existing compatibility shim also works with the Ruby 4 installation used to check this deck:

bundle exec ruby -r ./_plugins/ruby4_compat.rb -S jekyll serve --destination /tmp/rocksdb-site
